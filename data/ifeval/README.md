# IFEval Analysis Matrix

This directory contains the binary IFEval matrix used by the model-fitting
scripts.

## Matrix Construction

The starting point is the OpenEval response data from
`human-centered-eval/OpenEval`.  The raw OpenEval files are parquet shards, not
CSV files:

```text
item/ifeval-00000-of-00001.parquet
response/ifeval-00000-of-00004.parquet
response/ifeval-00001-of-00004.parquet
response/ifeval-00002-of-00004.parquet
response/ifeval-00003-of-00004.parquet
```

Those raw parquet files and the larger intermediate formatter outputs under
`data/openeval_ifeval_formatted_*` are intentionally not committed.  They can
be regenerated from the scripts.  The compact committed CSVs in this folder
are the files used by the fitting code.

The source formatter in
`scripts/data/format_openeval_binary_matrix.py` constructs a model-by-item
matrix as follows:

1. Read OpenEval response parquet shards for the requested benchmark(s).
2. Extract a model name, item id, and nested OpenEval score object for each
   response.
3. Recursively extract finite numeric values from the score object.  For
   IFEval, the score metric is `ifeval_strict_accuracy`.
4. Average those numeric values within each model-item pair.
5. Code the binary entry as `1` when the averaged score is at least the
   binary threshold, and `0` otherwise.  The default threshold is `0.5`.

Thus the entries are thresholded OpenEval strict-accuracy scores, interpreted
as the fraction of strict instruction checks satisfied for the prompt.

For IFEval, the OpenEval metric name is `ifeval_strict_accuracy`.  The raw
prompt-level values in the current snapshot are `0`, `1/3`, `1/2`, `2/3`, and
`1`, reflecting the fraction of strict instruction checks satisfied.  The
default analysis matrix uses `score >= 0.5`.  Sensitivity matrices for
`score >= 0.5`, `score >= 0.75`, and `score >= 1.0` are generated by
`scripts/ifeval/build_ifeval_threshold_matrices.sh`; the latter two thresholds
are identical for the current data because no scores lie in `(0.75, 1)`.

## Item And Instruction Metadata

The source formatter also parses the raw OpenEval item payload.  The retained
wide item table is:

```text
openeval_item_metadata.csv
```

It includes the raw JSON payload as well as explicit columns for `prompt`,
`instruction_ids`, `instruction_families`, `n_instructions`,
`n_unique_instruction_ids`, and `instruction_kwargs`.

The instruction-level table is:

```text
openeval_item_instruction_metadata_long.csv
```

It has one row per retained item-instruction pair.  For the default
`score >= 0.5` analysis, the final `534` retained items correspond to `820`
item-instruction rows, `25` unique instruction ids, and `9` instruction
families.  This is the metadata table to use when describing how the fitted
factor model compresses the original instruction-check space into a smaller
number of latent dimensions.

## IFEval Filter

The final analysis matrix is created by
`scripts/ifeval/create_ifeval_analysis_matrix.R`.  Starting from the full
OpenEval model-by-item matrix, it:

1. Selects item columns whose ids start with `ifeval_`.
2. Iteratively removes low-coverage models and items using the configured
   response-proportion thresholds.
3. Drops IFEval item columns with any missing model responses among the
   retained models.
4. Retains nonconstant IFEval item columns, meaning each retained item has at
   least one incorrect response and at least one correct response.

For the currently committed uncapped matrix, this starts from `124` models and
`541` IFEval items.  The analysis filter drops `2` low-coverage models,
`0` item columns for coverage or missingness after that model filter, and `7`
all-correct constant item columns.  The final matrix has `122` models and
`534` retained IFEval items.  The build summary is recorded in
`ifeval_analysis_matrix_build_summary.csv`.
